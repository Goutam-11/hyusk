### A8 — explicit policy registry

`tools/safety.rs` now owns a `ToolName` enum (one variant per registered
tool), an exhaustive `policy()` match with no wildcard, a row per tool with an
allow decision or an argument classifier, and the model-facing guidance for
that row. `requires_approval` is `policy_for(name)` plus the row's rule;
unknown tool names and unparseable arguments still ask.

`main.rs` grew `ToolSetup` and `build_tools`, so tool registration lives in one
function that a test can walk:
`tool_policy_tests::every_registered_tool_has_an_explicit_policy`. Verified by
temporarily registering a probe tool: the test failed with
`tools registered without an approval policy: ["ghost"]`.

Because unknown names now ask, the text and Sonic paths check that the tool
exists before arming a confirmation; otherwise a hallucinated tool name would
publish a card for a call that can never run. That reordering was verified
against the old order: `unknown_tool_name_reports_a_missing_tool_instead_of_arming_an_approval`
fails when the existence check is moved back after the gate.

`browser` is recorded as `Decision::Allow` — today's effective behaviour — and
left to D2, which is what A8's scope said.

### A1 — generated approval guidance

`prompts::approval_guidance_block()` renders `safety::approval_guidance()`
inside `build_system_prompt`, replacing the hand-written block that claimed
workspace tasks needed no confirmation, listed only part of the gated classes,
and told the model to ask before destructive actions. `user_profile_context`
and the per-turn note in the runner no longer pre-ask either.

### A2 — free research, preflighted workspace

`task_requires_approval` allows an explicit research profile (and an absent
one, which is the tool's default) and asks for everything else, so an unknown
profile fails closed. `task::canonical_workspace` resolves the root from the
call or `HYUSK_WORKSPACE` and is shared by the gate's pinning, the preflight,
and the worker. `task::delegation_preflight` checks the root and the `codex`
binary before a card is armed, in both the text and Sonic paths.

### Decisions taken beyond the issues' letter

- A2 resolves the workspace from `HYUSK_WORKSPACE` when the model names none.
  The acceptance line about a missing `HYUSK_WORKSPACE` needed the fallback to
  exist, and it keeps the approved root equal to the executed root.
- The preflight lives in `task.rs` (availability) rather than `safety.rs`
  (policy), with the runner calling it before arming.
- `Decision::Ask` was not introduced: no tool asks unconditionally today, so an
  always-ask tool would use a classifier that returns true. Keeping the variant
  would have been a dead-code warning.
